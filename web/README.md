# Lu portal (`web/`)

The user-facing front-end for **lu.dialectforge.com** (OP-007 / Port U).

Plain HTML + CSS + JS. **No npm, no axios, no bundler, no framework, no
build step.** Every file here is served verbatim. That is a standing
security constraint, not a style preference: there is no dependency tree
to audit and nothing between the source in git and the bytes on the wire.

## What it is

A two-screen PWA:

1. **Login** — one field, toggled between *owner passphrase* and
   *invite code*. Posts to `POST /auth`.
2. **Ask** — a conversation view over `POST /mcp` →
   `tools/call` → `lu4d_ask`.

## Files

| File | Role |

## API contract it depends on

From `crates/lu_guest_http/src/{main,auth,guest_mcp}.rs`:

```
POST /auth  {"passphrase":"…"} | {"invite_code":"…"}
  200 {"token":"…","principal":"owner"|"guest:<code>"}
  400 provide 'passphrase' or 'invite_code'
  401 invalid credentials

POST /mcp   Authorization: Bearer <token>
  {"method":"tools/list"}
  {"method":"tools/call","params":{"name":"lu4d_ask","arguments":{"query":"…"}}}
  200 {"result":{"content":[{"type":"text","text":"…"}],"structuredContent":{…}}}
  200 {"error":{"code":…,"message":"…"}}
  401 missing or invalid bearer token
```

### Three behaviours worth knowing

**Refusal is an answer, not an error.** `lu4d_ask` returns HTTP 200 with
`structuredContent.shape === "Refusal"` (the idk gate) or
`structuredContent.source === "greet_refusal"` (the pleasantry guard).
The UI renders both as a normal Lu turn labelled *Lu declined* — a
distinct card, deliberately **not** styled as an error. Honest refusal is
the anti-hallucination floor; presenting it as a fault would misrepresent
the product.

**401 means sign in again, never hang.** The guest binary keeps auth state
in memory (`auth.rs`: `tokens: Mutex<HashMap<…>>`), so restarting it
invalidates every issued token. Any 401 on `/mcp` clears local state and
returns to the login screen with a plain explanation.

**401 on `/auth` is deliberately ambiguous.** The server returns the same
`invalid credentials` for a wrong passphrase, an unknown invite code and an
already-redeemed one. The UI shows one message for all three and never
hints at whether a code exists.

## Serving

Caddy serves this directory as static files at `/` and reverse-proxies
`/auth`, `/mcp` and `/health` to `127.0.0.1:8787`. See `/etc/caddy/Caddyfile`.
Deploy target on the box is `/var/www/lu`.

```sh
# regenerate icons (needs Pillow)
cd web && python3 make_icons.py ../luAI.jpeg icons

# deploy
sudo rsync -a --delete web/ /var/www/lu/
sudo chown -R root:root /var/www/lu && sudo chmod -R a+rX /var/www/lu
sudo systemctl reload caddy
```

Bump `CACHE` in `sw.js` (`lu-shell-v1` → `-v2`) whenever a shell file
changes, or installed clients will keep serving the old one.

## Deliberately not built (v1)

* **Session tools.** `lu4d_session_start` / `lu4d_session_end` exist on the
  guest surface but mutate session state on a *process-global* brain shared
  by every signed-in user. Calling them per-login would let users stomp each
  other. Conversation continuity is kept client-side instead.
* **The Port U approval panel, wonder queue and cross-session search**
  internal notes. No endpoint exists for any of them on the guest
  surface — the whole reachable tool set is `lu4d_ask`,
  `lu4d_session_start`, `lu4d_session_end`.
