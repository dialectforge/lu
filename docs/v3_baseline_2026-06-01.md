**Date:** 2026-06-01
**Host:** the Lu server (Hetzner AX41-NVMe, Ryzen 5, 64 GiB RAM, 16 cores)
**Brain (copy):** `/tmp/brain.lbr.bench` (md5 `afaa88258f6c964505c852d90734a06a`, identical to production `/var/lib/lu/brain.lbr` at run start)
**Binary:** `crates/lu_brain_bench/src/bench_v3.rs` (release, single-threaded)
**Production binary unchanged:** `/usr/local/bin/lu_4_mcp` md5 `41f33466782fd1a2499a72ec38c44ff9`
**Curriculum-ingest service:** `inactive` throughout the run (training intentionally stopped for the port).
**Bench invocations:**
- Scenarios 1-3 (loaded brain): `bench_v3 --brain /tmp/brain.lbr.bench --keyfile /var/lib/lu/master.key --s3-n 20 --s3-progress-every 1 --skip-milestone-10m`
- Scenario 4 (fresh process, empty network): `bench_v3 --brain /tmp/brain.lbr.bench --skip-load` (full milestones including 10M)

## Scenario 1 — Bond add throughput

Inserts 100,000 synthetic bonds (`RelatedTo`, random weight, fresh target nodes) into the loaded production-copy brain via `AssociativeNetwork::add_bond`. Source seeds sampled uniformly from existing nodes; target nodes are freshly minted and registered via `add_node_unindexed` before the bond insert so the `add_bond` preflight (`contains_node`) succeeds.

- bonds attempted: 100,000
- bonds added: 100,000 (100%)
- wall-clock: 9.241 s
- **throughput: 10,822 bonds/sec**
- RSS delta: **+4,902 MiB** (17,224 -> 22,126 MiB)
- Implied marginal cost: **~51 KiB per added bond.** Much larger than the steady-state ~2.7 KiB/bond from Scenario 4. The delta is dominated by Lu's hub-degree bookkeeping path that triggers on `add_bond` (typed_ratio incremental update, adjacency vec growth on already-large hubs, keyword overlay churn for source-node indexing). Not pure per-bond cost.

## Scenario 2 — Single-subject read latency

`AssociativeNetwork::neighbors_outgoing(seed)` over a uniform random sample of existing seeds (mostly leaves under healthy growth curve).

- samples: 1,000
- **p50: 0.130 us (130 ns)**
- **p99: 0.780 us (780 ns)**
- mean: 0.212 us
- throughput: 4,147,450 reads/sec
- total bonds seen across reads: 1,694 (average out-degree ~1.7 — confirms leaf-dominated sample)

This is essentially a HashMap lookup over the in-RAM adjacency index. v4 will need to match this for the MemTable-hit path; the Block-cache miss path is the one v4 expects to be slower (mmap'd disk read + zstd decompress).

## Scenario 3 — Spread activation 2-hop latency

`spread_activation_weighted([(seed, 1.0)], Current, depth=2, top_k=50, ScarLog::new())`. Subjects sampled to have >=10 outgoing bonds (selected from 279 random candidates; the brain is leaf-heavy so >=10-out hubs are about 1-in-14).

- samples: 20 (reduced from the original 100 in the brief; see Notes for why)
- **p50: 6.74 s (6,742,408 us)**
- **p99: 36.20 s (36,196,467 us)**
- mean: 9.86 s
- range observed: 0.55 s (smallest) -> 36.20 s (largest)

This is the v3 bottleneck OP-BRAIN-V4 is designed to attack. Super-hubs (think anchor nodes for very common terms) blow up the 2-hop neighborhood into millions of bonds; the spread iterates them sequentially with degree-normalization and bridge bookkeeping. Subject-clustered SST layout + curiosity prefetch should bring p99 inside a single second for the v4 case.

## Scenario 4 — Resident RAM at bond-count milestones (fresh process, empty network)

Fresh `AssociativeNetwork::new()` in a process with no production brain loaded. Inserts synthetic bonds against a 1,024-node hub set with fresh target nodes per bond. Measures `/proc/self/status:VmRSS` after each milestone.

| Bonds      | RSS (MiB) | RSS (GiB) | Bytes/Bond |
|-----------:|----------:|----------:|-----------:|
| 10,000     |        30 |     0.029 |      2,907 |
| 100,000    |       246 |     0.240 |      2,546 |
| 1,000,000  |     2,722 |     2.658 |      2,852 |
| 10,000,000 |    25,457 |    24.86  |      2,669 |

Steady-state per-bond cost: **~2,650 bytes**. This includes the bond itself, both directions of adjacency vec entries, keyword index leakage from fresh node content (we use `add_node_unindexed`, but `add_bond` still wires source/target seeds into structures), and HashMap entry overhead. Consistent with the ~1.7 KiB-per-bond estimate from the port plan once node overhead is folded in.

**v4 target (per the port plan):** 13-byte CompactBond on disk + bounded MemTable resident -> resident RAM scales with working set (estimated ~5-10 GiB) instead of total brain size (this Scenario 4 trajectory).

Linear extrapolation: at the 6.7M-Wikipedia-article target (post-retrain projection ~600 GiB total) the v3 layout would need roughly 60x the 10M-bond cost. **OP-BRAIN-V4 must beat this curve, not match it.**

## Notes & caveats

- All times measured with `std::time::Instant` (monotonic), recorded in nanoseconds, reported in us/ms as appropriate.
- Single-threaded by design; the bench crate intentionally has no rayon / parallelization dependency. Phase 0 measures the v3 sequential baseline; v4 phases can re-bench in parallel mode for comparison.
- The brain file is a COPY of production at `/tmp/brain.lbr.bench`. Production `master.key` was used to decrypt. The bench binary never calls `Brain::save` — `--no-save` semantics are structural, not flag-driven.
- Scenario 3 sample count was reduced from 100 -> 20 because a first attempt with 100 samples ran past 10 minutes before being killed (the super-hub tail dominates). 20 samples still captures the p50/p99 character; full 100-sample run can be re-done overnight if a tighter p99 estimate is wanted, but the order-of-magnitude story is clear at n=20.
- Scenario 1 marginal cost (~51 KiB/bond) is much higher than Scenario 4 steady-state (~2.7 KiB/bond) because adding bonds to a heavily-archived production brain triggers overlay materialization paths (the archive's adjacency must be partially walked when a hub gets a new edge). This is *correct measurement* of the v3 add-bond path under production-shape conditions, not a setup artifact.
- Bench RNG seeded with `0xBABE_FACE_DEAD_BEEF` for reproducibility across re-runs (results will match modulo the inherent variance in hub sampling and OS scheduling).
- Production binary md5 verified unchanged at end of run: `41f33466782fd1a2499a72ec38c44ff9`.
